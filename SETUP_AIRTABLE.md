# Airtable backend — setup

> **Status:** the base, tables, fields, and seed records have been created
> programmatically. Base id: `appm3SLm7J5WuNr9Y`. The 1 manual step is
> adding the **Total Stock** formula field (Airtable's API can't create
> formula fields).

## Schema (already in place)

### Products table
- **Slug** (single line) — primary key. `retatrutide-10mg`, `ghk-cu-50mg`.
- **Name** / **Short Name** / **Family** / **Tagline** / **Short Description** / **Long Description** / **Bullets** / **Sequence** / **Molecular Weight** / **Purity** / **Size**
- **Base Price USD** / **Max Price USD** — dynamic pricing range
- **Stock** / **Full Stock** / **Low Stock At** — legacy / pricing thresholds
- **T Fridge** / **R Fridge** / **M Fridge** — per-fridge live counts (the
  source of truth for stock now)

### Orders table
- **Order ID** — auto-generated by the website (e.g. `TXJK4F2P9N`)
- **Customer** / **Email** / **Phone** / **Ship To**
- **Shipping Method** — `standard` / `austin-same-day`
- **Items** / **Total USD** / **Payment Amount** / **Payment Chain**
- **Tx Hash** — populated by the chain watcher when payment lands
- **Status** — `Pending payment` → `Paid` → `Shipped` → `Delivered` → `Cancelled`
- **Tracking Number** — fill in when you ship
- **Fulfilled From** — `T` / `R` / `M`. Auto-set when order is paid (highest
  fridge wins).
- **Notes**

## 1. Add the **Total Stock** formula field (10 seconds)

Open the Products table, click **+** at the right end of the columns:
- Type: **Formula**
- Name: `Total Stock`
- Formula: `{T Fridge}+{R Fridge}+{M Fridge}`

Now any change to T / R / M auto-updates the total. You can also delete the
old `Stock` number column — the website ignores it when fridge fields are
populated.

## 2. Restock workflow

When new inventory arrives, you bump the appropriate fridge in Airtable
(T / R / M). Total Stock recalcs automatically. The website's price
auto-adjusts too:

> Live price = `Base Price` (when total stock ≥ Full Stock)
> linearly stepping up to `Max Price` (when stock ≤ Low Stock At).

So `Stock = 8 → price = max`, `Stock = 60 → price = base`, anything in
between is interpolated.

## 3. Order workflow

| Step | What changes | Where |
|------|--------------|-------|
| Customer hits "Continue to payment" | Order row created with `Status = Pending payment` and a unique `Payment Amount` | Orders table |
| Customer sends USDC | Watcher finds the tx within ~5s | (background) |
| Match found | `Status = Paid`, `Tx Hash` filled, `Fulfilled From` set, the matching fridge decremented | Orders + Products |
| You ship | Manually flip `Status = Shipped`, paste **Tracking Number** | Orders table |
| Delivered | Manually flip `Status = Delivered` | Orders table |

The customer-facing `/order/[orderId]` page reflects every status change —
when you flip to Shipped + add tracking, they'll see it on their next
refresh.

## 4. Get an API key for the website

`.env.local` needs:

```
AIRTABLE_API_KEY=patzNS...your-token...
AIRTABLE_BASE_ID=appm3SLm7J5WuNr9Y
```

Use the same PAT you generated earlier — or revoke that one and create a
fresh, scoped-down token at airtable.com/create/tokens with:
- Scopes: `data.records:read`, `data.records:write`
- Access: only the **Texas Peptides** base

You don't need `schema.bases:write` anymore — that was just for the initial
provisioning.
